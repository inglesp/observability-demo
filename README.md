# observability-demo

Centralised logging for the droplets managed by [infra-demo-infra](https://github.com/inglesp/infra-demo-infra).

Every droplet forwards its logs with rsyslog, over mutual TLS, to one log droplet. That droplet runs three Dokku apps, built from the images in this repo:

| app | image | role | public? |
| --- | --- | --- | --- |
| `alloy` | `ghcr.io/inglesp/observability-alloy` | receives syslog on 6514/TCP (TLS), labels it, and pushes it to Loki | port 6514 only, from fleet droplets |
| `loki` | `ghcr.io/inglesp/observability-loki` | stores logs on its volume, kept for 30 days | no |
| `grafana` | `ghcr.io/inglesp/observability-grafana` | dashboards, with the Loki datasource and dashboards provisioned from this repo | HTTPS |

The apps share a Dokku network, and reach each other as `<app>.web`. Each image follows the fleet's contract: it runs as UID 10001, listens on port 8000, and keeps its data in `/data`.

CI builds the images on every pull request, and on pushes to `main` publishes them tagged `latest` and `sha-<commit>`. So changes to config or dashboards deploy like any app's: within a minute or so of the image being published.

The changes this needs in infra-demo-infra are in [`docs/infra-changes.md`](docs/infra-changes.md).

## Security

How a log line gets in, and why it can be trusted:

1. **Cloud firewall**: the log droplet accepts 6514/TCP only from fleet droplets. Because syslog runs over TCP, an off-path attacker can't fake a fleet IP and complete the handshake.
2. **Mutual TLS**: Alloy only accepts clients with a certificate signed by the fleet's private CA (generated by OpenTofu, one per droplet). rsyslog only sends to a server whose certificate is for the ingest name.
3. **Source IP label**: a syslog message's hostname is whatever the sender says it is, so Alloy also labels each stream with `source_ip`, the address the connection came from. The Deploys dashboard counts hostnames that have sent from more than one IP.

What's left: a compromised fleet droplet holds a valid certificate, so it can send false log lines, but only from its own IP.

The nginx log format has no client IPs, URLs or query strings.

## Labels

| label | from |
| --- | --- |
| `job` | always `syslog` |
| `host` | syslog hostname (self-asserted) |
| `source_ip` | the connection's source IP |
| `app_name` | syslog app name / tag, e.g. `deploy-event`, `nginx-access`, `systemd`, `sshd` |
| `level` | syslog severity |
| `app`, `result` | `deploy-event` lines only |
| `vhost` | `nginx-access` lines only |

## Dashboards

- **Deploys**: successful and failed deploys over time, by droplet and app, and a log of recent deploys. Also failed `deploy.service` runs as reported by systemd, which catch failures outside an app's deploy, such as `ansible-pull`. Built from lines the deploy service logs after each deploy:
  `event=deploy app=<app> image=<image> digest=<digest> result=success|failure duration_s=<n>`
- **nginx bytes**: bytes out (`$bytes_sent`) and in (`$request_length`) through Dokku's nginx on one droplet, by site and by status. Built from nginx's `bytes_json` access log format.

Dashboards are provisioned read-only. To change one, edit it in Grafana, export the JSON (Share → Export, without "Export for sharing externally"), and replace the file in `grafana/dashboards/`.

## Development

You need [just](https://github.com/casey/just), Docker and openssl.

```sh
just gen-test-certs   # a throwaway CA, server cert and client certs, in dev/certs/
just up               # Loki, Alloy, Grafana, and an rsyslog sender standing in for a droplet
just send-test-logs   # sample deploy events, a failed deploy run, and nginx access logs
just check-mtls       # Alloy accepts the CA-signed client cert and rejects others
just check            # build the images and check their config, as CI does
just down             # or `just reset` to also delete the data
```

Grafana is at http://localhost:3000 (admin/admin), and Alloy's UI is at http://localhost:8001.

## Upgrading

The base images are pinned in each Dockerfile. To upgrade:

1. Bump the pin.
2. Run `just check` and try the local stack.
3. Read Loki's upgrade notes for schema or config changes.
